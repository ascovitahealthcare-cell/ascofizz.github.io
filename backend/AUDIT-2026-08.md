# Codebase audit — August 2026

Full pass over all four repositories: security, payments, VitaPoints, refunds,
COD, workflow correctness, mobile, and SEO/GEO/AEO. Everything marked **FIXED**
is committed and pushed to `claude/hello-xtw814`.

Verification method: every finding was reproduced from the code path before
being fixed. The frontend fixes were then re-checked in headless Chromium at a
Pixel 7 viewport; the backend was boot-tested with all seven routers mounting.

---

## Critical

### 1 · Stored XSS through product reviews — FIXED

`reviews-routes.js` defined `const esc = v => String(v ?? '')`. Named like an
escaper, it escaped nothing. Review text and display names then went straight
into `innerHTML` on the storefront in three places: the product review list,
the testimonial cards and the featured-review wall.

The CSP allows `script-src 'unsafe-inline'`, so inline handlers execute. Any
customer with one genuine order could post `<img src=x onerror=…>` as their
review and run script in every visitor's browser on that product page.
`admin.html` is served from the same origin, so `localStorage` — where the
admin JWT lives — was reachable. That is account takeover from a product review.

Fixed at both ends: the backend escaper is real now, and all three render sites
use the `esc()` helper that already existed in `index.html` a few hundred lines
above and had simply never been applied here. The same no-op `esc` in
`returns-routes.js` (customer-written return reasons, rendered in the admin
panel) was fixed too.

Regression-tested in Chromium: the payload renders as inert text and
`window.__pwned` stays unset.

### 2 · VitaPoints were spent before the order was known to be valid — FIXED

`resolveVitaDiscount({commit:true})` reserves **and commits** — once it returns,
the points are gone from the customer's balance. It ran *first*, before:

- the COD value ceiling check
- the total-reconciliation check
- the duplicate-order check
- the stock check inside `sp_place_order`
- the Cashfree paid-amount check

Every one of those rejections took the customer's points and left no order
behind. The customer paid nothing, lost their balance, and the ledger had no
entry explaining it. `releaseVitaReservation()` existed for exactly this
situation and was **never called anywhere in the codebase**.

The Cashfree path was the worst of the five: by the time it commits, the
customer has already paid. A throw between commit and insert cost them the
money *and* the points.

Fixed:

| Path | Fix |
|---|---|
| `confirm-cod-order` | Reordered. Every rejection is now decided on a preview that reads the balance without touching it. Points commit only once the order is certain to be written. |
| `confirm-cod-order`, `/api/orders` | Release when `sp_place_order` fails (out of stock is the common case). |
| `confirm-gokwik-order` | Release on an unverifiable total and on an amount mismatch. |
| `cashfree verifyAndSaveCashfreeOrder` | Everything from commit to insert is wrapped: release, then rethrow so the failure is still reported. |

The duplicate branches deliberately do **not** release — there the order is
real, it was just created by the first of two calls, and
`vita_commit_redemption` is idempotent per order id.

### 3 · Site Images has been dead in production — FIXED

`site-media-routes.js` ended with:

```js
};site-media-routes.js
```

A stray copy of its own filename. JavaScript parses that as the expression
`site - media - routes.js`, so `require()` threw `ReferenceError: site is not
defined`, `server.js` caught it, logged `[mount] site-media-routes skipped`,
and every `/api/site-media` and `/api/admin/site-media` route was absent.

The admin panel's Site Images tab — logo, home hero slides, about photo, B2B
texture — has been silently non-functional. `node --check` passes on the file,
which is why it survived: the syntax is valid, it only throws on evaluation.

This matters right now: the rebrand plan tells you to swap old-logo imagery
through Admin → Site Images. That tab could not have worked. All seven routers
now mount.

## High

### 4 · Privilege escalation on product restore — FIXED

```js
app.put('/api/products/:id/restore', authMiddleware, async (req, res) => {
```

`authMiddleware` and nothing else. Any signed-in **customer** could un-delete a
discontinued product and put it back on sale. It shadows
`/api/admin/products/:id/restore`, which correctly requires
`requirePerm('products.delete')`. Now requires the same permission.

### 5 · VitaPoints economics were staff-editable — FIXED

`PUT /api/admin/vitapoints/config/:key` and `POST /api/admin/vitapoints/release-now`
were `adminOnly`. `vita_config` sets what a point is worth, the per-order
redemption cap and the milestone threshold. `release-now` skips the delivery +
return-window hold that stops a refused COD parcel from minting spendable
points.

Both are money, so under the v9.3 role split both are owner-only — the same
reasoning already applied to `coupons.manage` ("a coupon is a discount, i.e.
money"). Reading the config stays open to staff so they can answer a customer's
balance question.

### 6 · Every product advertised as out of stock to Google — FIXED

The catalogue JSON-LD in `<head>` is hand-written and static, so it can only
describe the build. All 16 offers carried
`availability: https://schema.org/OutOfStock`, because the static `PRODUCTS`
array ships `stock: 0` and real stock arrives from the backend a moment later.

Google has been reading the entire catalogue as out of stock. That alone is
enough to drop products out of rich results and Merchant listings, and no
amount of keyword work compensates for it.

Fixed with `syncProductStructuredData()`, which rewrites price and availability
from live stock after the backend merge and adds `aggregateRating` where real
reviews exist. Verified in Chromium: 16/16 offers flip to `InStock` and gain a
rating once stock arrives.

### 7 · Product URLs had no product markup — FIXED

A single-page app serves the same `<head>` for every URL, so `/product/<slug>`
carried only the 16-item `ItemList` — which describes sixteen products at once
and matches none of them specifically.

`setProductPageSchema()` now writes a page-scoped `Product` block when a
product opens, with live price, availability, SKU, canonical URL and rating,
and removes it on the way out so two products are never described at once.
Google executes JS before indexing, so this is what gets read.

Ratings are only ever emitted when backed by real reviews. Inventing one is a
structured-data violation and a manual-action risk — and the storefront
already refuses to display a fabricated star count, so emitting one in the
markup would have contradicted the page.

## Medium

### 8 · Shopify webhook 500 on a malformed signature — FIXED

`crypto.timingSafeEqual` throws a `RangeError` when the buffers differ in
length, and `X-Shopify-Hmac-Sha256` is attacker-controlled. A one-character
signature header turned what should be a clean 401 into an unhandled
exception. Lengths are compared first; any throw is now a failed verification.

### 9 · `'★'.repeat(rating)` could take down the review list — FIXED

`String.repeat()` throws a `RangeError` on a negative count. Ratings come from
the database and were used unchecked in three render paths, so a single bad row
would have blanked the whole review section. Added `starCount()`, which clamps
to 0–5.

## Verified sound — no change needed

These were checked and are genuinely well built. Listing them so you know they
were looked at, not skipped.

- **Server-side totals.** `computeServerSideTotal()` reprices every line from
  the products table on every order path. A tampered cart cannot change what a
  customer pays.
- **Cashfree webhook.** Real HMAC-SHA256 over `timestamp + rawBody`, compared
  with `timingSafeEqual`, rejecting unsigned requests.
- **GoKwik webhook.** Re-verifies every "paid" event against GoKwik's own API
  rather than trusting the callback body.
- **Order idempotency.** Every payment path is idempotent per order id, so a
  webhook and a client confirm racing each other cannot create two orders or
  double-award points.
- **`assertRealOrder()`.** Binds shipping-label creation to the order's stored
  pincode, so a stranger cannot redirect a real order to their own address.
- **Guest order tracking.** Selects only the tracking columns; the earlier
  `select('*')` IDOR that leaked name, phone and full address is gone.
- **Gemini advisor.** No longer an open proxy — only the user's text crosses
  the boundary, with the model, system instruction and output ceiling fixed
  server-side.
- **Token revocation.** Privileged tokens carry a version claim checked on
  every request; 1-hour admin sessions vs 30-day customer sessions.
- **Returns.** Partial returns are priced from the order's own stored line
  items, never from the request, with an idempotency key on the reversal.
- **Marketing service auth.** `INTERNAL_API_KEY` gate that fails **closed** —
  an unset key returns 503 rather than reverting to open.
- **Mobile.** No horizontal overflow on `index.html` or `admin.html` at a
  Pixel 7 viewport. Every `<img>` has an `alt`. `viewport-fit=cover` is set.
  Zero page errors on either.

## Not fixed — needs your decision or access I do not have

1. **`GET /api/track/:awb` is unauthenticated** and proxies any AWB through
   your Shiprocket credentials. Someone enumerating AWBs could read shipment
   status for parcels that are not theirs. It returns no address or contact
   data, so the impact is low, but binding it to an order id the way
   `/api/track-order/:orderId` does would close it.

2. **23 tap targets under 24px** on a phone viewport (mostly inline text links
   and the filter-clear button). Below Google's recommended 24px minimum and a
   minor Core Web Vitals / usability signal. Cosmetic, and fixing it means
   touching shared link styles — worth doing deliberately rather than in a
   security pass.

3. **`sw.js` is never registered.** No `serviceWorker.register()` call exists
   anywhere, so the PWA is dormant. I bumped the cache name to `ascofizz-pwa-v6`
   so any browser holding a legacy registration self-heals rather than serving
   old branding forever, but I did not register it — turning a service worker
   on for a live site is a deliberate decision with real caching consequences.

4. **`assets/hero-acv-reset.svg` and `assets/hero-ashwagandha.svg`** are
   referenced by `admin.html` and do not exist in the repository. Pre-dates
   this work. Supply them or drop the references.

5. **Blog.** `/blog` is in the sitemap, `_redirects` and the navigation, but
   there is no blog content or `BlogPosting` schema. An indexable URL with
   nothing on it is worse than no URL. Either publish posts or remove `/blog`
   from the sitemap until you do — you asked about blogs for SEO, and this is
   the honest answer: the slot exists, the content does not, and content is the
   part I cannot generate for you truthfully.

6. **Backlinks.** Nothing in a codebase creates backlinks. What the code can do
   it now does: valid `Organization`, `LocalBusiness` and `Person` schema with
   consistent NAP, an `llms.txt` for answer engines, and clean canonical URLs.
   The rest is outreach — supplement directories, Indian D2C roundups, the
   the corporate site linking to the storefront, and your Google
   Business Profile.

7. **Old-brand artwork.** Any product photo, banner or ad creative whose
   *image* shows the Ascofizz logo still shows it. Renaming a file does not
   repaint it. See the deployment notes.
